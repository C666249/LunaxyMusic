# Lunaxy Music V82 — 歌词搜索独立执行域与状态机修复

基线：V81。

本轮仅修复歌词搜索调度/状态机，不修改网易/QQ歌词适配器，不恢复本地歌单/收藏/历史歌词扫描。

## 根因
V80/V81 的歌词索引和真实 LRC 核验虽然有专属线程池，但外层仍先提交到 MainActivity 共享 `io` 线程池。共享池繁忙时，歌词任务可能长时间排队；UI fail-safe 却按点击后的墙钟时间提前把 `lyricSearchPending` 置 false，于是先显示“没有找到歌词命中”，真正任务稍后才运行并补出结果。

## 修复
1. 网易/QQ歌词索引直接提交到 `lyricIndexExecutor`，不再经过共享 `io`。
2. 每个真实 LRC 核验任务直接提交到 `lyricSearchExecutor`，不再经过共享 `io` 协调层。
3. 删除基于固定墙钟时间强行结束 pending 的 fail-safe；“没有找到歌词命中”只在两条专用远程索引都完成、网易/QQ普通远程候选兜底也已考虑、且所有已启动核验任务完成后才允许出现。
4. 两条歌词索引分别完成、分别合并，任意一路先返回即可立即显示候选并启动真实歌词核验，不再互相等待。
5. 第一条真实 LRC 命中仍立即绘制，不等待整批候选。
6. 本地收藏/歌单/历史歌词扫描继续保持删除状态。

Locked Core：播放、下载、Provider、Canonical Track 等核心链路不修改。
