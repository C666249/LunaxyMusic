# V92.9.14 Validation Log — Artwork-Driven Loading & Playlist Hero Color

## Trigger

V92.9.13 已经把搜索、每日推荐/智能集合与歌单详情的加载统一为逐行楼梯式 reveal，但移动光缝与部分占位材质仍然使用固定蓝色；歌单详情顶部大卡片也仍依赖平台/来源预设色。V92.9.14 的目标是把两处统一到真实封面色，同时保持既有楼梯节奏与 Shared Hero 几何不变。

## Runtime implementation

- `FluidPlaceholderView`
  - Skeleton accent 改为可在运行中更新。
  - `setAccent()` 只重绘，不重启 shimmer animator，因此封面晚到时不会让楼梯动画回到起点。
  - `isSongRow()` 用于仅重染歌曲行占位，避免误改其它 skeleton。
- `CurtainRevealFrame`
  - 去除固定蓝色移动光缝；新增可更新 accent。
  - 光缝使用当前 accent 与白色按明/暗模式混合，再生成透明边缘，保留玻璃高光而不回退到统一蓝色。
- `MainActivity`
  - `progressiveLoadingAccent()` 优先读取当前播放歌曲封面 accent，并以 `playlistPlaybackAccentKey` 绑定当前歌曲/封面身份。
  - 新曲封面尚未解析时使用页面自己的 fallback，不沿用上一首歌的 accent。
  - 当前封面异步解析完成后，`retintProgressiveLoadingRows()` 原地更新仍可见的 Skeleton 与 Curtain seam。
  - Search-All、Smart Collection、歌单详情 placeholder batch 共用同一动态取色路径。
  - 歌单详情 Hero 首帧优先使用内存缓存中的歌单首张封面 accent；异步封面返回后以约 260ms 的短插值更新玻璃材质。
  - `PlaylistHeroSnapshot` 与活动中的 `PlaylistHeroMorphView` 同步使用歌单封面色，Shared Hero 前后不出现两套颜色。
- `PlaylistHeroMorphView`
  - 新增运行中 `setAccent()`，允许 Shared Hero 在封面解析完成时同步换色。
