# V92.9.11 validation log

## Trigger / real-device finding

User video from V92.9.10 showed two perceptual failures despite the existing shared-object plumbing:

1. playlist card → detail still read as a near-instant page replacement; the source card did not visibly own the transition long enough;
2. playlist skeletons were correct, but real rows resolved so close together that the handoff looked like a snap instead of a readable left→right curtain.

## Implemented choreography

- Shared playlist travel uses one reversible progress value, ~680ms for a full push/pop.
- Source card / cover / title / metadata remain the primary object first; destination title/actions, subtitle, Back, song header and row skeletons join later through staged progress windows.
- Detail artwork target increased to 88dp so the source card visibly grows rather than merely changing pages.
- Shared overlay adds a shallow zero-at-endpoints flight arc and subtle accent aura.
- Full-page right-edge clipping was removed from the playlist shared transition; the root library gently recedes while the detail surface remains opaque.
- First real playlist row materialization waits ~560ms during shared navigation.
- `CurtainRevealFrame` now exchanges content/skeleton ownership spatially: content reveals from the left, placeholder survives on the unresolved right, a feathered light seam travels between them, and the row simultaneously settles vertically/fades in.
- Curtain duration: 470ms; materialized rows start on an overlapping 62ms cascade.
